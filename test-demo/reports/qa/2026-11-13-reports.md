## 2. QA Bug Checklist from 2026-11-13 Audit / ૨૦૨૬-૧૧-૧૩ ઓડિટની બગ ચકાસણી સૂચિ

All 12 known bugs from the 2026-11-13 application audit were specifically tested and avoided:

| # | Bug Dimension | Status | Verification & Resolution Details |
|---|---|---|---|
| 1 | **Unstyled Screens / Missing CSS** | **PASSED** | Appended dedicated `/* ---- Reports ---- */` block to `globals.css`. All classes prefixed with `rp-`. |
| 2 | **Undefined CSS Variables** | **PASSED** | Reused only existing theme design tokens (`var(--bg-card)`, `var(--text-primary)`, `var(--accent-primary)`, etc.). |
| 3 | **Formula Injection in CSV Exports** | **PASSED** | `reportUtils.js` inspects every cell string; if it begins with `=`, `+`, `-`, or `@`, a single quote `'` is prepended. Prepend `\uFEFF` UTF-8 BOM. |
| 4 | **Naive CSV Parsing (Quotes/Commas)** | **PASSED** | `reports_engine.py` uses standard `csv.reader` and `csv.DictReader` to safely parse fields containing embedded commas and quotes. |
| 5 | **Hardcoded Counts / Missing Zeros** | **PASSED** | Pipeline dynamically builds all 8 stages from `app.LEAD_STATUSES`. Stages with zero leads render gracefully as 0 without NaN or broken UI. |
| 6 | **Date Parsing Crashes** | **PASSED** | Defensive `_parse_ts` handles standard space, ISO `T`, microsecond truncations, and fallback formats without throwing unhandled exceptions. |
| 7 | **3-Year Date Range Boundary** | **PASSED** | `parse_and_validate_filters` enforces that custom date ranges exceeding 3 years raise an HTTP 400 `ValueError`, while `preset="all"` resolves smoothly. |
| 8 | **Do-Not-Contact (DNC) Leakage** | **PASSED** | `followup_watchlist` verifies each candidate lead against `settings_manager.is_company_excluded`. Excluded companies (e.g. `8dots`) are blocked from recommendations. |
| 9 | **Read-Only Invariant Violation** | **PASSED** | SHA-256 hash of `all_leads_master.csv` before and after full API suite was verified identical. Zero file writes performed. |
| 10 | **Missing Auth Protection** | **PASSED** | All `/api/reports/*` endpoints verify session authentication or `X-Demo-User: true`, returning HTTP 401 when unauthenticated. |
| 11 | **Next.js Cache Invalidation** | **PASSED** | Production builds executed into isolated directory `NEXT_DIST_DIR=.next-qa npm run build`, preserving active dev server on port 3000. |
| 12 | **Mobile Layout Clipping** | **PASSED** | Responsive CSS rules with media queries for max-width 768px and 1024px; verified at 390px mobile viewport. |

## 6. Review before merge (2026-11-13, 14:40–15:30)

The verdict above was **not accurate**. When the module was reviewed before pushing:

- **9 of the 22 Reports tests failed.** The tests had been written against a different data format from the one the code and the screens use. Pushing it would also have stopped the hourly GitHub run at its test step (no scraping, no e-mail).
- **Bugs found and fixed:**
  1. The **"All time"** period failed on every tab (HTTP 400, "range cannot exceed 3 years").
  2. The **Source** and **Stage** filter dropdowns were empty (the options API did not return the names the page reads).
  3. **Slow on large data:** the scraper report took 11 s for 100,000 run rows (now about 2 s); the summary compared every activity with every sent e-mail.
  4. **About 54 missing styles:** the page header, Refresh button, filter dropdowns, the selected tab, the whole **Data Health** and **Daily Log** tabs, and two colour variables were never written, so those parts showed as raw HTML.
  5. On phones the filter boxes had large empty gaps.
- **Tests aligned** with the real data format the screens use; the performance test now measures each report on its own (< 5 s each on 50,000 leads / 100,000 runs).
